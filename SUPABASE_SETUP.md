# 🗄️ Настройка Supabase для HyperLink

## 📋 Что такое Supabase?

Supabase — это open-source альтернатива Firebase, предоставляющая:
- PostgreSQL базу данных
- Аутентификацию пользователей
- Хранилище файлов (Storage)
- Real-time подписки
- REST API автоматически

## 🚀 Пошаговая настройка

### Шаг 1: Создание проекта в Supabase

1. Перейдите на [supabase.com](https://supabase.com)
2. Зарегистрируйтесь или войдите в аккаунт
3. Нажмите **"New Project"**
4. Заполните форму:
   - **Name**: `hyperlink` (или любое другое)
   - **Database Password**: придумайте надёжный пароль (сохраните его!)
   - **Region**: выберите ближайший к вам регион
   - **Pricing Plan**: Free (для начала достаточно)
5. Нажмите **"Create new project"**
6. Дождитесь создания проекта (~2 минуты)

### Шаг 2: Создание базы данных

1. В Supabase Dashboard перейдите в **SQL Editor** (иконка терминала в боковом меню)
2. Нажмите **"New Query"**
3. Скопируйте содержимое файла `supabase/schema.sql`
4. Вставьте в SQL Editor
5. Нажмите **"Run"** (или Ctrl+Enter)
6. Дождитесь успешного выполнения

Проверьте, что созданы таблицы:
- Перейдите в **Table Editor**
- Должны быть таблицы: `users`, `links`, `link_services`, `clicks`, `page_views`

### Шаг 3: Настройка Storage для обложек

1. Перейдите в **Storage** (иконка хранилища в боковом меню)
2. Нажмите **"New bucket"**
3. Заполните:
   - **Name**: `covers`
   - **Public bucket**: ✅ включено
4. Нажмите **"Create bucket"**

### Шаг 4: Получение API ключей

1. Перейдите в **Settings** → **API** (в боковом меню)
2. Скопируйте два значения:
   - **Project URL**: `https://xxxxx.supabase.co`
   - **anon public key**: длинная строка, начинающаяся с `eyJ...`

### Шаг 5: Настройка переменных окружения

1. В корне проекта создайте файл `.env` (или скопируйте `.env.example`):

```bash
cp .env.example .env
```

2. Откройте `.env` и вставьте ваши значения:

```env
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

⚠️ **ВАЖНО**: 
- Никогда не коммитьте `.env` в git!
- Файл `.env` уже добавлен в `.gitignore`

### Шаг 6: Создание первого пользователя

#### Вариант А: Через Supabase Dashboard

1. Перейдите в **Authentication** → **Users**
2. Нажмите **"Add user"** → **"Create new user"**
3. Заполните:
   - **Email**: ваш email
   - **Password**: ваш пароль
   - **Auto Confirm User**: ✅ включено
4. Нажмите **"Create user"**
5. Скопируйте **UUID** пользователя
6. Перейдите в **Table Editor** → **users**
7. Нажмите **"Insert row"**
8. Заполните:
   - **id**: UUID из шага 5
   - **email**: ваш email
   - **name**: ваше имя
   - **plan**: `free` или `pro`
9. Нажмите **"Save"**

#### Вариант Б: Через SQL

```sql
-- Создайте пользователя в Authentication, затем выполните:
INSERT INTO public.users (id, email, name, plan)
VALUES (
  'ВАШ_UUID_ИЗ_AUTHENTICATION',
  'your@email.com',
  'Ваше Имя',
  'pro'
);
```

### Шаг 7: Запуск приложения

```bash
# Установите зависимости (если ещё не установлены)
npm install

# Запустите dev-сервер
npm run dev
```

Откройте `http://localhost:3000` и войдите с данными из шага 6.

## 🔐 Безопасность

### RLS (Row Level Security)

В схеме уже настроены политики безопасности:
- Пользователи видят только свои данные
- Публичные ссылки видны всем
- Клики и просмотры публичны для аналитики

### Переменные окружения

- `anon key` безопасен для использования на клиенте (он имеет ограниченные права)
- Никогда не используйте `service_role key` на клиенте!
- Для продакшена настройте дополнительные ограничения в Supabase Dashboard

## 🐛 Решение проблем

### Проблема: "Supabase не настроен"

**Решение:**
1. Проверьте, что файл `.env` существует
2. Проверьте, что переменные заполнены правильно
3. Перезапустите dev-сервер (`npm run dev`)

### Проблема: "Failed to upload cover"

**Решение:**
1. Проверьте, что бакет `covers` создан
2. Проверьте, что бакет публичный
3. Проверьте размер файла (макс. 5MB)

### Проблема: "Permission denied"

**Решение:**
1. Проверьте, что RLS политики созданы
2. Проверьте, что пользователь создан в Authentication
3. Проверьте, что пользователь есть в таблице `users`

### Проблема: Данные не сохраняются

**Решение:**
1. Откройте DevTools → Console
2. Проверьте на наличие ошибок
3. Проверьте Network tab для API запросов
4. Проверьте Logs в Supabase Dashboard

## 🔄 Миграция с localStorage

Приложение работает в двух режимах:

### Режим 1: Без Supabase (localStorage)
- Данные хранятся локально в браузере
- Обложки конвертируются в base64
- Подходит для демо и разработки

### Режим 2: С Supabase
- Данные хранятся в облачной БД
- Обложки загружаются в Supabase Storage
- Подходит для продакшена

Приложение автоматически переключается между режимами в зависимости от наличия конфигурации Supabase.
