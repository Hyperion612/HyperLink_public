# 🔌 Страница подключения к Supabase

## ✅ Что добавлено

### 1. Кнопка "Для разработчиков" на главной странице
- Расположена под основными кнопками
- Переходит на страницу `/connect`
- Стиль: тёмно-серый с синим акцентом ⚡

### 2. Страница подключения (`/connect`)
- Форма для ввода Supabase URL и Anon Key
- Автоматическая проверка подключения
- Синхронизация всех данных из localStorage в Supabase
- Пошаговая инструкция по настройке
- Визуальные индикаторы статуса (успех/ошибка)

### 3. Автоматическая синхронизация
После успешного подключения:
- Все пользователи синхронизируются
- Все ссылки и сервисы переносятся в облако
- Вся аналитика (клики, просмотры) загружается в Supabase
- Данные сохраняются в localStorage как резервная копия

## 🚀 Как использовать

### Шаг 1: Подготовка Supabase

1. Создайте проект на [supabase.com](https://supabase.com)
2. Выполните SQL схему:
   - Перейдите в **SQL Editor**
   - Скопируйте содержимое `supabase/schema.sql`
   - Нажмите **Run**
3. Создайте бакет для обложек:
   - Перейдите в **Storage**
   - Нажмите **New bucket**
   - Название: `covers`
   - ✅ Public bucket
   - Нажмите **Create bucket**

### Шаг 2: Получение credentials

1. Перейдите в **Settings** → **API**
2. Скопируйте:
   - **Project URL** (например: `https://abcdefg.supabase.co`)
   - **anon public key** (длинная строка, начинающаяся с `eyJ...`)

### Шаг 3: Подключение

1. Откройте главную страницу HyperLink
2. Нажмите кнопку **"Для разработчиков"**
3. Вставьте:
   - Supabase URL
   - Supabase Anon Key
4. Нажмите **"Подключить Supabase"**
5. Дождитесь проверки и синхронизации (~5-10 секунд)
6. После успешного подключения автоматически перейдёте на дашборд

## 🔄 Режимы работы

### Режим 1: localStorage (без Supabase)
- Данные хранятся только в браузере
- При очистке кэша данные теряются
- Подходит для тестирования

### Режим 2: Supabase (облако)
- Данные хранятся в PostgreSQL
- Доступ с любого устройства
- Автоматическая синхронизация
- Резервное копирование

### Хранение конфигурации

Конфигурация Supabase хранится в localStorage:
- `supabase_url` — URL проекта
- `supabase_key` — Anon Key
- `supabase_configured` — флаг "true"

Приложение автоматически определяет наличие конфигурации и переключается между режимами.

## 🔐 Безопасность

### Anon Key
- Безопасен для использования на клиенте
- Имеет ограниченные права (только RLS политики)
- Не даёт доступа к service_role функциям

### RLS политики
- Пользователи видят только свои данные
- Публичные ссылки видны всем
- Клики и просмотры публичны для аналитики

### Рекомендации
- Никогда не коммитьте `.env` с credentials
- Используйте переменные окружения для продакшена
- Регулярно делайте бэкапы базы данных

## 🐛 Решение проблем

### Проблема: "Ошибка подключения"

**Возможные причины:**
1. Неверный URL или Key
2. Проект не создан в Supabase
3. SQL схема не выполнена
4. Бакет `covers` не создан

**Решение:**
1. Проверьте URL и Key в Settings → API
2. Убедитесь, что проект активен
3. Выполните `supabase/schema.sql` в SQL Editor
4. Создайте бакет `covers` в Storage

### Проблема: "Ошибка синхронизации"

**Возможные причины:**
1. Таблицы не созданы
2. RLS политики блокируют доступ
3. Недостаточно прав

**Решение:**
1. Проверьте, что все таблицы созданы
2. Проверьте RLS политики в `supabase/schema.sql`
3. Убедитесь, что используете `anon key`, а не `service_role key`

### Проблема: Данные не синхронизируются

**Решение:**
1. Откройте DevTools → Console
2. Проверьте на наличие ошибок
3. Проверьте Network tab для API запросов
4. Проверьте Logs в Supabase Dashboard
